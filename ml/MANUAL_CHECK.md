# Ручная проверка приложения со стендом

Порядок проверки приложения на реальных данных AutoGRAPH и реальной модели через стенд `ml/fleet_service`
(состояние плана — шаг 4). Выполняет человек: реальные ключи, учётные данные и устройство в автоматические
проверки не попадают. Секреты (`.env`, токены, пароль) никуда не пересылать — ни в чат, ни в задачи.

## 0. Автоматические проверки

```bash
.claude/skills/fleet-check/check.sh     # gradle testDebugUnitTest + assembleDebug, оба pytest, smoke.sh
```

`smoke.sh` гоняет стенд через compose с подставными OpenRouter и AutoGRAPH. Пока здесь есть красное — на устройство
не идти.

## 1. Настройки стенда (`.env`)

```bash
cd ml
cp fleet_service/.env.example fleet_service/.env
cp predictive_antifraud/.env.example predictive_antifraud/.env
```

- `fleet_service/.env`: `FS_OPENROUTER_API_KEY`, `FS_LLM_MODEL`, `FS_PREDICTIVE_API_KEY`.
- `predictive_antifraud/.env`: `PA_API_KEY` — то же значение, что `FS_PREDICTIVE_API_KEY`.

Ключ аналитики — общий секрет двух сервисов, его придумывают сами:

```bash
openssl rand -hex 32     # или: python3 -c "import secrets; print(secrets.token_hex(32))"
```

Пустые оба — проверка `X-API-Key` отключена (только для локальной разработки: в compose аналитика открыта на порту
хоста 8001). Разные значения — аналитика отвечает стенду 401; проверка правилами при этом работает, а поле
`analytics` в ответе `/v1/anomalies/check` показывает ошибку.

Остальные `FS_*` можно оставить по умолчанию; хранилище аномалий (SQLite) лежит в томе compose `fleet_data`.

## 2. Запуск стенда и проверка без приложения

```bash
docker compose up -d --build                                             # fleet_service :8080, predictive_antifraud :8001
curl -s localhost:8080/health                                            # {"status":"ok","llmConfigured":true}
curl -s localhost:8001/health
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/v1/vehicles      # 401 — без токена стенд не отвечает
```

`llmConfigured: false` — не заданы `FS_OPENROUTER_API_KEY` или `FS_LLM_MODEL`.

## 3. Сборка и установка debug-APK

```bash
source scripts/env.sh && ./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Связь телефона со стендом:

- по USB (проще): `adb reverse tcp:8080 tcp:8080`, адрес в приложении — `http://127.0.0.1:8080`;
- по Wi-Fi: адрес `http://<IP ПК>:8080`, телефон и ПК в одной сети, порт 8080 открыт в файрволе.

HTTP без TLS разрешён только в debug-сборке; release ходит на стенд только по HTTPS.

## 4. Базовая линия — старый путь

1. Онбординг: реальные данные (не демо), свой логин AutoGRAPH.
2. Все переключатели стенда выключены.
3. Запомнить (лучше скриншотами), что показывают для 1–2 машин за 6 ч и 24 ч: «Сводка», таблицы, графики.
4. «Уведомления» → «Проверить сейчас» — запомнить найденные аномалии.

С этим сравниваются следующие шаги.

## 5. Переключатели — по одному

⚙ Настройки → «Стенд» → «Адрес стенда» → «Сохранить адрес». Дальше включать по одному и проверять:

| Переключатель | Что проверить |
|---|---|
| «Данные через стенд» | Таблицы, графики, сводка, карточка аномалии по тем же машинам и периодам совпадают с базовой линией; лента не сбросилась |
| «Ассистент через стенд» | «Какие у меня машины?», «Проверь <машина> за сутки» — числа в ответах совпадают с таблицами; чат из карточки аномалии знает, о какой аномалии речь |
| «Аномалии со стенда» (раздел «Аномалии») | «Проверить сейчас» находит то же, что на устройстве. В debug — «Сравнивать с устройством (отладка)» и `adb logcat -s AnomalyCompare`: расхождений нет |
| «Хранить аномалии на стенде» (вместе с «Аномалиями со стенда») | Лента и карточка приходят со стенда, локальная история перенеслась; «Подтвердить» / «Ложная тревога» переживают перезапуск приложения; второй телефон или пользователь той же схемы видит те же решения; новые события дают пуш, повторная проверка не плодит дубли |

## 6. Отказы и откат

- `docker compose stop fleet_service` — приложение показывает понятную ошибку на русском и не падает;
  после `docker compose start fleet_service` всё восстанавливается.
- Все переключатели выключены — старый путь работает как в п. 4.

## 7. Логи стенда без секретов

```bash
docker compose logs fleet_service | grep -iE 'session=|bearer|password=|sk-or'
```

После каждого маркера — только `***`.

## Если что-то не так

Собрать для разбора:

- пункт проверки, что ожидалось и что получилось;
- фрагмент `docker compose logs fleet_service` (маскируется автоматически, но перед отправкой просмотреть глазами);
- `adb logcat` с ошибкой.

## Куда уходит токен сессии AutoGRAPH

Для справки при проверке логов и трафика:

- приложение получает токен через `Login` и держит его только в памяти; логин и пароль — в DataStore на устройстве;
- на стенд токен уходит в `Authorization: Bearer`, вместе с `X-Schema-Id` и `X-User-Name` (логин без пароля);
- стенд проверяет токен через `EnumSchemas` (кэш — по SHA-256 токена) и передаёт его в AutoGRAPH как `session=`;
- в OpenRouter, `predictive_antifraud` и базу аномалий токен не попадает.
