# Telegram-бот «Петровича» (telegram_bot)

Бот даёт быстрый доступ к стенду без приложения. Он присылает события парка, позволяет принять решение по событию,
разобрать его с ассистентом, отправить письмо сотруднику и настроить подписку. Сценарии и тексты взяты из макетов
«Прототип Telegram-бота «Петрович»». Сейчас сделаны экраны 1–5, 7, 8 и 11:

| Макет | Что в боте |
|---|---|
| 1. Старт | `/start` без подключения: что умеет бот и код для ввода в приложении |
| 2. Подключение и меню | код из бота введён в приложении (или `/start <код>` по ссылке на том же телефоне) → «Вы подключены к схеме…»; меню команд и кнопки «Что у меня не так?», «Проблемы», «Настройки» |
| 3. Уведомление и решение | карточка события: важность, машина, время, описание, «Петрович помнит»; «Подтвердить», «Ложная тревога» с причиной (Штатная работа / Ошибка датчика / Уже известно / Другое — текстом), «Вернуть в работу». Кто и когда решил — видно всем, в том числе в приложении |
| 4. Разбор | «Разобраться с Петровичем»: ассистент стенда отвечает по этому событию (`anomalyId`), вопросы — текстом, «Завершить разбор» |
| 5. Письмо сотруднику | черновик от ассистента (кому, тема, текст, срок) с кнопками «Отправить» / «Отменить»: письмо уходит только по кнопке |
| 7. Утренний доклад | в выбранное время (по умолчанию 09:30, каждый день или по будням): события за сутки по подписке, по типам — машина и время; «Разобрать по порядку» (карточки неразобранных одна за другой), «Открыть ленту». Сразу — `/report` |
| 8. Недельная сводка | в выбранный день и время (по умолчанию понедельник 09:30): события за прошлую неделю против позапрошлой, частые типы, решения, машины с наибольшим числом событий, машины без событий. Сразу — `/week` |
| 11. Настройки и подписки | `/settings`: мои машины, типы событий, предупреждения, инфо, лимит в день, тихие часы, отключить бота. То же — в приложении: Настройки → Telegram |

Ещё есть `/problems` (события, которые ждут решения), `/park` (машины и неразобранное по ним), `/new` (разговор
заново) и `/help`. Голос, графики, выгрузки CSV/Excel/PDF и отчёт по группе (макеты 4 — голосом, 6, 9, 10) — следующие шаги.

## Как устроено

```
Telegram ⇄ telegram_bot (aiogram, long polling) ⇄ fleet_service (/v1/*, /v1/telegram/*) ⇄ AutoGRAPH
```

- **Подключение** — в приложении: Настройки → Telegram. Два пути:
  - **код из бота** (Telegram на любом устройстве): неподключённому чату бот в ответ на /start или любое сообщение
    присылает код `XXXX-XXXX` (`POST /v1/telegram/bot/pair-code`), пользователь вводит его в приложении
    (`POST /v1/telegram/pair`), бот здоровается в чате;
  - **ссылка** (Telegram на том же телефоне): приложение просит у стенда ссылку `POST /v1/telegram/link`
    (`https://t.me/<бот>?start=<код>`), Telegram открывает бота, `/start` передаёт код стенду
    (`POST /v1/telegram/bot/connect`).

  Коды одноразовые, живут 15 минут. Чат привязывается к схеме и логину пользователя.
- **Доступ к AutoGRAPH.** Своего пароля или токена у бота нет. Стенд работает от имени пользователя по доступу
  фоновой проверки, который его приложение уже выдало (`background_access`). Поэтому ссылку можно получить, только
  когда включена «Фоновая проверка на стенде». Пока жив токен сессии, бот работает. Если включено «Разрешить стенду
  входить самостоятельно», бот работает и без телефона. Если доступа нет, бот один раз в 12 часов пишет, что нужно
  открыть приложение.
- **Запросы.** Бот обращается к обычным `/v1/*` стенда с заголовками `Authorization: Bearer <TB_STAND_TOKEN>` и
  `X-Telegram-Chat-Id`. Стенд сам подставляет схему и сессию пользователя чата. Автором решения и письма становится
  логин пользователя из подключения, а не заголовок. Выдавать доступ фоновой проверки и ссылки бот не может (403).
- **Уведомления.** Бот раз в `TB_OUTBOX_INTERVAL_SECONDS` забирает выдачу `POST /v1/telegram/bot/outbox`. Новые события
  находит фоновая проверка стенда, а стенд решает по подписке чата, что и куда отправить:
  - «Критично» по выбранным машинам приходит всегда;
  - предупреждения и инфо приходят, если включены и подходят по типу, не в тихие часы и в пределах лимита на сутки;
  - пропущенное потом не досылается;
  - одно событие уходит в чат один раз;
  - больше 5 событий за раз — одной строкой «И ещё N событий…».
- **Состояние разговора** (история для ассистента, разбор, ожидание причины) хранится в памяти бота: перезапуск
  начинает разговор заново. Подключения, подписки и решения хранятся на стенде. Короткие ключи кнопок лежат в SQLite
  (`TB_DATA_PATH`): callback_data в Telegram — до 64 байт, а id аномалий длиннее. Кнопки старых уведомлений работают
  и после перезапуска.
- **Подписка** хранится на стенде, поэтому бот и приложение показывают одно и то же. Машины, события (выключенное не
  приходит, даже критичное, и не видно в списках), важность, лимит и тихие часы настраиваются и в боте (`/settings`), и
  в приложении: Настройки → Telegram. Остальное — только в приложении:
  - антиспам повторов (в карточке — «повторялось ещё N раз»);
  - списки `/problems` и `/park`: только выбранные машины, важность, период, сколько строк, порядок. Выключенные
    события в списках не показываются. Бот пишет, какой фильтр действует;
  - состав карточки: какие строки и кнопки показывать.
- Пользователь заблокировал бота — чат отключается на стенде.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather), сохраните токен и имя.
2. На стенде (`ml/fleet_service/.env`): `FS_TELEGRAM_BOT_USERNAME=<имя без @>`,
   `FS_TELEGRAM_SERVICE_TOKEN=<случайный ключ, openssl rand -hex 32>`. Нужна включённая фоновая проверка
   (`FS_ACCESS_ENCRYPTION_KEY`). `/health` стенда покажет `"telegramConfigured": true`.
3. Бот (`ml/telegram_bot/.env` из `.env.example`): `TB_BOT_TOKEN`, `TB_STAND_TOKEN` — тот же ключ, что
   `FS_TELEGRAM_SERVICE_TOKEN`.
4. ```bash
   cd ml && docker compose --profile telegram up -d --build
   ```
   Без профиля `telegram` бот не запускается, и стенд работает как раньше.

Локально, без compose:

```bash
cd ml/telegram_bot
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env    # TB_STAND_URL=http://127.0.0.1:8080
.venv/bin/python -m telegram_bot
.venv/bin/pytest
```

Сквозной тест (логика бота против настоящего стенда с подставным AutoGRAPH) лежит в
`ml/fleet_service/tests/test_telegram_bot_e2e.py`. Он запускается, если пакет бота установлен в окружение стенда:
`pip install -e ml/telegram_bot`.

## Устройство кода

| Файл | Что |
|---|---|
| `logic.py` | всё поведение: команды, текст, кнопки → ответы (текст и кнопки); без Telegram, проверяется тестами |
| `bot.py` | адаптер aiogram: доставка ответов, «печатает…», цикл уведомлений |
| `texts.py` | тексты по макетам (HTML Telegram), данные стенда экранируются |
| `stand.py` | клиент стенда: ключ бота и id чата в заголовках, отказ — `StandError` с текстом для пользователя |
| `refs.py` | короткие ключи кнопок в SQLite |
